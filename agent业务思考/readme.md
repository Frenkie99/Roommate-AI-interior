# Roommate-AI-interior 架构分析：Workflow vs Agent

> 2026-05-21 讨论记录

## 项目概述

项目：[Roommate-AI-interior](https://github.com/Frenkie99/Roommate-AI-interior)
定位：AI 驱动的智能室内设计平台，用户上传毛坯房照片，生成装修效果图，支持局部精修和知识问答。

核心功能：
- 毛坯房照片 → 选择风格 → 生成装修效果图
- SAM3 智能分割 → 选中区域 → 对话式局部精修
- RAG 知识问答（DeepSeek + Chroma，21 条装修知识）
- 内置评测平台（CLIP Score / Structural Fidelity / LLM Judge）

技术栈：React 18 + FastAPI + Gemini API + Segmind SAM3

---

## 核心判断：这是 Workflow，不是 Agent

### 判定依据

系统的执行路径是**确定性的、用户驱动的、代码预定义的**：

```
上传照片 → 前端校验 → 后端预处理 → 调 Gemini API → 返回效果图 → 用户预览/下载
```

每一步的输入输出是确定的，不存在"模型自主决定下一步做什么"的环节。

### Workflow vs Agent 对比

| 维度 | 当前项目 (Workflow) | Agent 系统 |
|------|-------------------|-----------|
| 控制流 | 代码预定义，用户驱动 | 模型自主决策，动态规划 |
| 工具调用 | 固定顺序调 API | 模型根据情况选择用哪个工具 |
| 错误处理 | 预设逻辑（重试、降级） | 模型自主判断并调整策略 |
| 记忆/状态 | 无跨轮次自主记忆 | 有工作记忆，能从失败中学习 |
| 目标分解 | 用户手动拆解任务 | 模型自主拆解复杂目标 |

## 逐环节分析：Agent 是否有价值？

### 1. 图像生成管线 → 不需要 Agent

**原因：用户意图已被 UI 收窄。**

用户上传照片 + 选风格 + 选房间类型，三步已经把意图压缩到非常具体的范围。6 维度 prompt engineering 是人类专家知识的编码，不需要模型临时推理。

加 agent 的代价：
- 不确定性：用户要北欧风，agent 推荐日式原木 → 用户困惑
- 延迟：多一轮推理多几秒
- 失控感：装修是高度个人偏好的事

### 2. 对话精修 → 不需要 Agent

用户说"温馨一点"，用一个 LLM 调用映射到几种操作的组合（换暖色灯光、加地毯、换布艺沙发）就够了，这是**单步推理**，不是 agent 循环。

如果 agent 自主决定"先换沙发 → 再改灯光 → 再加地毯"，每步调 API 生成图片，成本和时间翻倍，用户可能看到中间结果就喊停。

### 3. RAG 知识问答 → 不需要 Agent

单一数据源（21 条装修知识）的 RAG 是确定性流程：query → embed → retrieve → generate。不存在"需要跨多个工具协调"的场景。

### 4. 评测平台 → 有 Agent 潜力，但不是现在

如果评测数据积累到几百上千条，"评测分析 agent"可以自动发现 badcase 模式、建议 prompt 优化方向。但 85 个样本用 Streamlit dashboard 看看就够了。这是**数据规模驱动的需求**，不是架构驱动的。

## 核心洞察

### 为什么当前场景不需要 Agent

项目的根本特征：**用户意图的表达窗口很窄。**

用户通过 UI（上传照片、选风格、选房间类型）已经把意图说清楚了。Agent 的价值在于处理**开放式的、意图模糊的、需要多步探索的任务**——但当前场景不具备这个特征。

### 真正需要 Agent 的场景长这样

```
用户："我想让这个房间看起来更高级一些，预算不限"

Agent 需要：
  分析房间结构 → 判断采光 → 推荐风格方向 → 生成 3 个方案
  → 用户选一个 → 深入调整 → 对比材质 → 最终定稿
```

这个流程有多轮决策、有分支、有用户反馈循环，agent 才有意义。

而当前场景是：上传照片 → 选"现代轻奢" → 生成。单轮、确定性、高效率。

---

## 混合架构建议（如果要引入 Agent）

**保持 workflow 主体不变**，只在一个地方加 agent 能力：**"智能设计师对话"入口**。

```
现有流程（不变）：
  上传照片 → 选风格 → 生成 → 精修 → 下载

新增入口（agent）：
  用户："我想装修这个房间，不知道选什么风格"
  → Agent 分析房间 → 推荐 2-3 个风格 → 用户选择 → 进入现有 workflow
```

这个 agent 只做一件事：**帮犹豫不决的用户做决策**。决策完成，立刻交棒给 workflow。agent 不碰生成管线、不碰编辑管线、不碰 RAG。

最小侵入，解决的是"选择焦虑"问题。

---

## 结论

**当前 workflow 架构是正确的选择。** 不要为了"用 agent"而用 agent。

当场景真正需要"模型自主规划多步行动"的时候，agent 自然就是正确的选择——但那一天不是今天。
