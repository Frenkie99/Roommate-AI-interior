---

## 北极星

> **从「发现一张烂效果图」→ 定位根因（prompt？分割？参数？）→ 改 → 复测验证 的闭环耗时。**

评测的终极产出是**迭代闭环**，不是好看的分数报告。每个功能都要问：它是否在缩短这个闭环。

---

## 评测成熟度阶梯（我们的坐标系）

```
L0  纯人工看图，无系统
L1  有评分器，能批量出分、出报告        ← 当前位置（且有裂缝：2/3 评分器已被数据判死）
L2  评分器「可信度」被量化证明           ← 地基已铺好（credibility.py + gold_store.py），但金标准 0 条，从未通电
L3  评测集达标（难度分层 / 真实为主 / 难case 领先当前能力）
L4  执行自动化（视觉模型 Judge / 多模型投票纠偏 / Agent 看护重试）
L5  评测直接驱动代码自动迭代（北极星）
```

**当前真实位置：站在 L1，L1 自身有裂缝；L2 代码就绪但未运转。目标 L5。**

## 分阶段计划

> 状态标记：⬜ 未开始 · 🟡 进行中 · ✅ 完成。每阶段都有明确「完成标准 (DoD)」，达标才进下一阶段。

### 阶段 0 — 让系统第一次通电（免费，~30min）✅ 完成 2026-06-21
- **动作**：建 venv → 装轻量三件套（streamlit/pandas/Pillow）→ 启动看板 → 确认金标准标注界面能打开。
- **DoD**：`streamlit run evals/ui/app.py` 能打开，「金标准标注」tab 可见、可操作。
- **结果**：venv `evals/.venv` 建成；三件套就位；看板 http://localhost:8501 启动正常；冒烟测试通过（85/85 图片可显示）。

### 阶段 1 — 给评分器定生死（免费，用户标注）✅ 完成 2026-06-21
- **动作**：在标注界面标金标准（structural/aesthetic/instruction/overall，1-5 分）→ 读「评分器可信度」面板。
- **DoD**：拿到每个评分器 vs 人工金标准的 Spearman/Pearson/归一MAE，对 clip/structural_fidelity/llm_judge 各下一句**有数据支撑**的判决。
- **结果（85/85 全标，显著阈值 |Spearman|≈0.21）**：
  - 🔴 clip_score：vs 综合 -0.26 / vs 美学 -0.31，**显著负相关 → 反指标，弃用**。
  - 🔴 llm_judge：±0.21 内偏负 → **纯噪声（盲评），判死，需视觉模型重做**。
  - 🟡 structural_fidelity：vs 结构 +0.17 → **唯一正向但未达显著，阶段 2 抢救**。
  - **总判决：当前自动评测无任何可信信号。**

### 阶段 2 — 重验本地评分器（免费）⬜
- **动作**：装重依赖（torch/cv2/skimage/transformers）→ 重跑 `structural_fidelity`、决定 clip 修或弃 → 用阶段1金标准量化验证。
- **DoD**：至少 1 个本地评分器的可信度被量化证明达标，可作为后续可信信号。

### 阶段 3 — 上视觉模型 Judge（押后，花钱）⬜
- **动作**：把图**真正发给** Gemini 视觉模型替换盲评 DeepSeek + 多模型投票纠偏 + 量化方差。
- **DoD**：视觉 Judge 与金标准对齐度显著优于现盲评，方差可控。

### 阶段 4 — 评测驱动代码自动迭代（远期，红线之后）⬜
- **动作**：评测暴露某类烂图 → Agent 钻代码分析对应 prompt/编排/参数 → 改 → 复测 → 提 PR。
- **前提**：阶段 1-3 评分器可信度达标。**不可跳过。**

---

## 红线（不可逾越）

1. **评分器可信度未被量化证明前，不上自动改代码闭环**——否则噪声放大成对生产代码的错误修改。
2. 顺序不可颠倒：**先固评分器 → 再建好评测集 → 最后才谈自动闭环。**
3. 图像任务的评委**必须真正看见图**，不照搬文本场景的「让 LLM 读日志」。
