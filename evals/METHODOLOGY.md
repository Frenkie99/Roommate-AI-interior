# 评测方法论（Eval Methodology）

> 本文档是评测平台的**顶层设计哲学与落地准则**，所有评测相关改动应先对齐这里的原则。
> 来源：综合「张和老师 · Agent 时代评测体系：变与不变」的方法论，并**抽象 + 适配**到本项目
> （室内设计图像生成，垂直多模态场景）。原文偏 Agent/文本 trace 场景，本文档已做场景翻译。

---

## 0. 本项目的场景定位（决定哪些原则适用）

- 我们**不训练图像模型权重**：核心 AI 能力是调用外部模型（API易 Gemini / Segmind SAM3 / DeepSeek）。
- 我们唯一的优化杠杆是：**提示词、分割/编辑 pipeline、参数、编排代码、后处理**——即 Agent 工程侧。
- 因此原文凡讲"训练集 / 标注训练数据 / 模型迭代"的，对我们**降级理解**为"pipeline 当前能力边界 / prompt 与编排迭代"。
- 评测核心三维度：**结构保真（墙/窗/承重不能乱）+ 美学质量 + 指令遵循（风格/房型/需求）**。
- 关键差异：我们的"trace"是**一张图**，不是文本日志。**图像评测必须用视觉模型**，不能照搬"让 LLM 读文本 trace"。

---

## 1. 北极星指标：迭代闭环周期（不是报告）

评测的终极产出是**迭代闭环**，不是好看的分数报告。若只能留一个北极星指标，选：

> **从「发现一张烂效果图」→「定位根因（prompt？分割？参数？）」→「改」→「复测验证」的闭环耗时。**

推论：评测平台的每个功能，都要问"它是否在缩短这个闭环"。只产出分数、不能回溯根因的功能，价值有限。

---

## 2. 四条不变的哲学（含本项目翻译）

1. **终极产出是迭代闭环，不是报告。**（见上）

2. **评测集要"略微领先于当前能力"。** 原文是"领先训练集"；我们没有训练集，翻译为：
   评测集要持续放入 pipeline **现在还做不好**的难 case（复杂户型/异形采光/多房间/模糊指令），
   而不是堆我们已经稳的简单卧室。**只能测出已经会的东西，对优化毫无价值。**

3. **好评测集三铁律：**
   - ① **难度故意比真实世界更难**：40% 简单中等、20–30% 偏难、永远留 10–20% 极难；
     真实世界万分之一的极端 case 放大到 ~1%（"撵驴原则"，但别走极端到曲高和寡）。
   - ② **以真实数据为主**：真实毛坯房照片为主，合成图占比 ≤ 20–30%（评测集体量小，单位成本撑得起真实数据）。
   - ③ **单位投入是训练集的 10–100 倍**：值得请懂行的室内设计人士来定标注基准。

4. **Look at your data。** 再漂亮的总分也代替不了亲眼看 bad case。
   对图像任务尤其致命——**CLIP 分/结构分只是信号，不是真相**。
   评测平台的真正价值：让人从一个低分 case，一路下钻到「原图 + 生成图 + 指令 + 各分项」并排回溯根因。

---

## 3. 评分器可信度准则（本项目当前重点）

**核心命题：评分器的价值不在"能打分"，而在"打的分可信"。可信度必须先可度量，才能谈提升。**

可信度 = 两个可量化维度：

- **对齐度（Validity）**：自动分与**人工金标准分**的相关性。用 Spearman / Pearson / MAE 度量。
  - 没有金标准就没有对齐度——所以**人工打分必须结构化沉淀**（不能停留在"我心里有数"）。
- **稳定性（Reliability）**：同一对图重复打分的方差。LLM/视觉 Judge 准确率会浮动（典型 90–95%），
  必须量化它的波动；只要下游有人工校验，方差就能算出来，并在使用时做补偿。

**纠偏手段（来自原文，统计学正面应对不确定性）：**
- 多模型投票取最大公约数（无标准答案时用顶尖模型当参照物）。
- 算出系统性偏差后，在输入端放宽补偿；引入异构数据源，避免单评分器出错就全军覆没。

**红线：在评分器可信度被量化证明之前，不要上"评测自动改代码"闭环——**
否则评分器的噪声会被自动放大成对生产代码的错误修改。**先固评分器 → 再建好评测集 → 最后才谈自动闭环。**

---

## 4. 自动化分层（执行环节，从人工走向 Agentic）

> 原则：哲学不变，但每个执行环节都可被 Agent 重写以提升自动化效率。按 ROI 排优先级，不要一次全上。

1. **数据采集与标注**：人工挖掘标注 → Agent 漏斗（挖掘/清洗/预标注分层质检）。*我们数据量未到海量，中低优先级。*
2. **Trigger（哪条数据值得进评测集）**：规则关键词匹配 → 语义理解（小模型/视觉模型按结构化标准判断评测价值）。
3. **执行打分**：纯代码 workflow → **agentic workflow**（本项目最实在的升级面）：
   - ① **LLM-as-Judge → Agent / 多模型投票 Judge**。⚠️ 图像任务必须用**视觉模型**，把图真正发过去。
   - ② **死脚本 → Agent 看护**：批量生成遇 API 限流/超时/偶发失败时自动重试、退避、记录现场。
   - ③ **用统计学纠偏**：量化 Judge 方差，按偏差补偿，异构数据源兜底。
4. **报告**：死网页 → 动态可交互、可点选、可下钻、可回溯。**图像任务做图像专属可视化**
   （原图/效果图并排、结构 mask 叠加、分项雷达图）。我们已有 Streamlit，是现成抓手。

---

## 5. 终极闭环：评测直接驱动代码自动迭代（远期靶子）

把上述环节串起来：评测一旦暴露某类烂图 → Agent 钻进代码库分析对应 prompt / 编排 / 参数 → 根据 bad case
改代码 → 跑通后提 PR。对**我们这类 Agent 工程产品尤其契合**，因为优化点恰恰是"改 prompt / harness / 编排"，
正是 Agent 最擅长改的东西。

**前提（不可跳过）**：第 3 节的评分器可信度必须先达标，否则闭环会自动把代码改坏。这是终局，不是起点。

---

## 6. 给"半研究员型 PM"的定位

评测不需要从零训模型，需要的是：对数据有直觉、对场景有判断、愿意 look at your data、能用 Agent 工具
快速把想法做成 demo 验证。和工程/算法**共创**评测集、评价标准，而不是站在门外提需求。

---

## 7. 适配红线小结（避免被"大佬范式"带偏）

- 原文场景是 Excel Agent（文本/表格 trace），**我们是图像生成**——别把精力误投到"让 Agent 读日志"，
  要投到"让视觉模型可靠地评图"。
- "评测自动改代码"很性感，但它是**终局**：根因前提是评分器可信，顺序不能颠倒。
- 大佬的"三个月闭关 + 985 博士标注"是其资源假设。我们取**与自身资源匹配的最小可行子集**，不做全套复刻。

## 8. 实证案例（本项目 2026-06，面试可直接讲述）

> 把上面的抽象原则，钉死在一次真实的端到端实践上。讲给面试官时，价值在于**每个结论都有统计证据**，不是"我觉得"。
> 完整进度见 `PROGRESS.md`，可信度代码见 `scorer/credibility.py`，消融见 `scorer/structural_ablation.py`。

**背景**：一个室内设计图像生成产品，有 3 个自动评分器（clip_score / llm_judge / structural_fidelity），
但从没人验证过它们的分到底可不可信，长期靠人工主观打分。

**做法（半天，零成本起步）**：
1. 人工标 **85 条金标准**（结构/美学/指令/综合 四维 1-5 分，刻意用满全程、覆盖好中差）——这是度量可信度的唯一真值。
2. 算每个评分器自动分 vs 人工金标准的 **Spearman 相关**（n=85 的显著阈值 ≈ 0.214）。

**结论（三个评分器全被证伪/分级）**：
- 🔴 **clip_score 是"反指标"**：vs 人工美学 **-0.31**，显著负相关。根因——图-图相似度评"毛坯→精装"，
  效果图越像空毛坯（=设计越烂）相似度越高，语义是反的。**若信它去优化，会朝错误方向越走越远。**
- 🔴 **llm_judge 是噪声**：所有维度都在 ±0.21 内。根因——它是"盲评"，只把文本喂给 LLM，从不看图。
  图像任务的评委必须真正看见图。
- 🟢 **structural_fidelity 抢救成功**：用消融实验发现旧版 60% 权重的 Canny 边缘 SSIM 几乎零相关（+0.08，
  被新增家具边缘淹没），换成 64×64 低分辨率布局 SSIM 后 **+0.17 → +0.42**（过显著线，2.5 倍）。

**四条可迁移的经验**：
1. **"能打分 ≠ 分可信"**：评分器的价值在分可信，而可信必须先用人工金标准量化，才能谈提升。
2. **度量驱动迭代**：病根靠消融实验测出来，不拍脑袋；修完用同一把尺验证涨了多少。
3. **拒绝过拟合**：lowres32 能到 +0.434 也不追，因为它比 lowres64 只高 0.017，在 n=85 下是采样噪声。
   **知道何时停手，比榨干小数点更重要。**
4. **好指标聚焦单维**：新结构评分器对美学/指令近零相关，是优点——它只测结构、不越界假装测别的。

**红线复述**：所以在评分器可信度达标前，绝不上"评测自动改代码"闭环——否则噪声会被放大成对生产代码的错误修改。

## 9. 外部权威阅读的增补（2026-06-29）

> 来源：Anthropic《Demystifying evals for AI agents》+ Hamel Husain evals 合集（《Your AI Product Needs Evals》《LLM-as-a-Judge》
> 《Field Guide》《Evals FAQ》《Revenge of the Data Scientist》等）。逐篇提炼与本项目适配/冲突见 `READINGS.md`。
> 本节只收「能升级顶层哲学、且本文前 8 节没有」的洞见；大量实操细则留在 READINGS.md 当弹药库。

**先说被强力印证的（说明我们方向对）**：这些权威材料与本文第 1/3/8 节高度同源——「Look at your data 是 ROI 最高」「LLM-Judge 必须当分类器对照人工标签验证」「Criteria Drift：标准在看数据中长出来」「单一领域专家定标」「自建领域查看器」「拒绝通用指标」。我们用 85 条证伪 3 个评分器、先标后建、few-shot 锚定 + 留出验证，全部踩在正道上。Hamel 一句「**The harness is data science**」可直接用于面试叙事。

**补充进方法论的新框架（前 8 节缺的）**：

1. **能力评测 vs 回归评测（来自 Anthropic，本项目缺这个区分）。**
   - 能力评测(capability)：起点低分、专挑模型现在做不好的、给「可攀登的山」——对应我们的**路径B 难 case**。
   - 回归评测(regression)：维持~100% 通过、防改 prompt 改崩——对应我们**已稳的简单房型**。
   - 成熟的能力评测「毕业」转为回归套件持续跑。**行动：把 85 条按此二分，让迭代有明确的「攻什么(能力)、守什么(回归)」。**

2. **非确定性度量 pass@k / pass^k（来自 Anthropic）。** pass@k=k 次至少一次对；pass^k=k 次全对（面向用户要每次都稳）。
   我们当前每个输入只生成一张图、未测「同输入多次生成」的方差——是个缺口（中优先级）。

3. **饱和度意识（来自 Anthropic）。** 100% 通过=已饱和，只能防回归、不再有改进信号；0% 通过通常是任务坏了不是模型菜。

4. **二元 Pass/Fail + 书面 critique（Hamel 篇篇强调）。** ⚠️与我们 1-5 Likert 金标准有张力，但**不是推翻**：
   Likert 用于「算可信度 Spearman」是对的（需序数方差）；但我们金标准**缺 critique（书面理由）**=缺 few-shot 素材、缺标准显性化、缺错误分析原料。
   **行动：下轮人工分析给（失败的）样本补「二元判定 + 两句 critique」，与 1-5 分并存，各喂各的用途。**

5. **错误分析要 bottom-up：开放编码(open coding)→轴心编码(axial coding)→理论饱和（Hamel）。**
   我们「失败地图」是 top-down 按 metadata 切片——还没做过真正的「亲读 bad case 写观察、让分类涌现」。
   **红线：open coding 必须人(frenkie)亲做，不可外包/不让 AI 代归类。** 这是模块四下一步主攻。

6. **分层防护 Swiss Cheese（来自 Anthropic）：** 自动评测 + 生产监控 + 人工读 trace，无单层能兜住所有问题。

**一处重要张力（两位权威互相矛盾，我们取中道）**：Anthropic 主张「能力评测可先于能力建立（赌未来模型）」，Hamel 主张「**别做 eval-driven development，只写发现的错误、不写想象的错误**」。
二者都对，区别在前瞻 vs 务实。**本项目取中：主力评测来自错误分析（已发现的真实失败），少量当能力靶子（路径B）。**

**不变的红线再确认**：以上新框架不松动第 3 节红线——评分器可信度达标前，不上自动改代码闭环；先看数据、先把闭环用可信的那一维手动跑通。

## 10. 产品契约与金标准裁决规则的耦合（2026-07-09）

**发现**：grader 的 pass/fail 定义无法先于产品承诺存在——"失败/成功标准清晰"（课程）的前提是产品立场清晰。
实证：产品对不利输入（窄视角/歪斜拍摄）会自发做视角矫正与扩图，好看了但不一定还原原貌——
这算 pass 还是 fail，取决于产品承诺的是"忠实还原"还是"效果优化"。

**已定调的裁决线（呈现 vs 内容）**：纯视角矫正=呈现优化，不扣分；拓扑改变/面积虚构=内容造假，fail。
完整规则、四点产品判断与待办清单见 `PRODUCT_CONTRACT.md`（2026-07-09 仲裁已按此执行，
few-shot 池 critique 已按此线编码）。

**方法论沉淀**：仲裁一条 3 分模糊 case 逼出了藏两个月的产品契约问题——模糊地带不是标注负担，
是产品决策的探针；这正是"人工看数据不可替代"的又一实证。
